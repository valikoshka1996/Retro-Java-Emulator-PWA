## Про проєкт

Java Retro — український застосунок для старих кнопкових **J2ME / Java ME** ігор. Усередині працює справжній [FreeJ2ME Web](https://github.com/zb3/freej2me-web) через CheerpJ: MIDlet виконується у браузері та отримує події клавіатури, графіку й звук.

**Профіль → імпорт JAR → аналіз налаштувань → гра → RMS-збереження → повторний запуск із прогресом.**

Реєстрація та серверна база даних не потрібні. Профілі, JAR і резервні копії зберігаються в локальній IndexedDB; застосунок не завантажує ваші JAR на свій сервер. Домен production-проєкту: **[retrojava.pp.ua](https://retrojava.pp.ua)**; налаштування reverse proxy та SSL описані нижче.

## Швидкий старт

Потрібні **Node.js 24.x**, **npm** та **Java 8** у `PATH`. Достатньо JRE: скрипт завантажить перевірений Eclipse ECJ compiler. Базовий runtime і вихідний код FreeJ2ME вже є у `vendor/`.

```bash
git clone https://github.com/valikoshka1996/Retro-Java-Emulator-PWA.git
cd Retro-Java-Emulator-PWA

npm ci
npm run engine:prepare
npm run dev
```

Відкрийте **http://127.0.0.1:5173/**.

> Перший запуск CheerpJ потребує інтернету й може тривати кілька хвилин. Використовуйте ту саму адресу надалі: `localhost`, `127.0.0.1`, різні порти та домени мають окремі сховища.

## Від першого JAR до першого збереження

1. **Створіть профіль:** ім’я, аватар — і можна додавати ігри.
2. **Імпортуйте власний `.jar`:** перетягніть його до бібліотеки або виберіть через файловий діалог. Ліміт — **32 МБ**. Супровідний однойменний `.jad` можна вибрати разом із JAR.
3. **Перегляньте аналіз:** рекомендований телефон і роздільність можна змінити в **Налаштування → Advanced**. Рекомендація є припущенням, а не гарантією сумісності.
4. **Натисніть «Грати»:** використовуйте клавіатуру, gamepad або екранні кнопки.
5. **Збережіться всередині гри:** якщо вона використовує RMS, дані потраплять до локального сховища.
6. **Перед виходом натисніть «Стоп»:** дочекайтеся завершення сесії та фінальної копії RMS.
7. **Запустіть гру знову:** вона прочитає власні збереження цього профілю.

### 📱 Повний екран і клавіатура телефона

**«На весь екран»** відкриває гру разом із керуванням. Якщо браузер не підтримує Fullscreen API або відмовляє у запиті, застосунок автоматично займає доступну область вікна й прибирає власні панелі. На iPhone системний статус і панелі Safari можуть залишатися; для окремого вікна встановіть PWA через «На початковий екран». Кнопка **«Вийти»** повертає звичайний інтерфейс без зупинки гри.

Екранна клавіатура має форму кнопкового телефона: soft keys і навігація зверху, цифри **3 × 4** під ними. У портретному ігровому режимі вона розміщується під грою, у горизонтальному — поруч із нею. Підтримуються одночасні дотики.

Натисніть **«Вигляд клавіатури»** у плеєрі або **«Клавіатура»** в ігровому режимі. Доступні три пресети, чотири теми, ширина, висота кнопок, відступи, заокруглення, вирівнювання та літери під цифрами. Перед збереженням є попередній перегляд. Налаштування окремі для кожної гри, застосовуються без перезапуску емулятора й входять до архіву профілю. На малому екрані розміри автоматично обмежуються, щоб залишити місце грі. Також редактор доступний у картці гри: **«Клавіатура» → «Вигляд екранної клавіатури»**.

### Перевірка без сторонніх ігор

У порожній бібліотеці натисніть **«Додати RMS Probe»**. Це власний відкритий тестовий MIDlet:

- **Enter / OK** — збільшити лічильник і записати RMS.
- **1** — відтворити тестовий тон.
- **0** — завершити MIDlet.

Після «Стоп» і нового запуску на екрані має з’явитися попереднє значення `RMS READ`. Вихідний код тесту є в `java/`; комерційні ігри до репозиторію не включені.

### Керування за замовчуванням

| Дія                   | Клавіші         |
| --------------------- | --------------- |
| Напрямок              | `↑` `↓` `←` `→` |
| OK / Fire             | `Enter`         |
| Ліва / права soft key | `F1` / `F2`     |
| Цифри телефону        | `0`–`9`         |
| `*` / `#`             | `E` / `R`       |

У розділі **Клавіатура** можна змінити кожне призначення або вибрати пресет. Конфліктні клавіші не зберігаються. Стандартний gamepad: D-pad / лівий стік — напрямок, A — OK, B / X — soft keys, Y — 5, Start — 0. Відповідність фізичного контролера залежить від браузерного mapping.

## Збереження та перенесення бібліотеки

| Спосіб              | Для чого                                                     |
| ------------------- | ------------------------------------------------------------ |
| **RMS**             | Внутрішні постійні збереження Java ME гри                    |
| **Резервний слот**  | Копія RMS із назвою, датою та скріншотом; до п’яти на гру    |
| **Експорт RMS**     | ZIP зі збереженнями конкретної гри                           |
| **Експорт профілю** | JAR/JAD, налаштування, RMS, слоти та історія в одному архіві |

**Створити копію:** відкрийте **Збереження → Створити слот** під час гри. **Відновити:** спочатку зупиніть гру, потім виберіть потрібний слот і натисніть **«Відновити»**.

**Перенести все:** **Налаштування → Експорт профілю**, потім імпортуйте ZIP на іншому пристрої або домені. Імпорт створює окремий профіль із новими ID.

> Слоти відновлюють RMS, а не точний момент гри. Повні JVM snapshots недоступні. Автокопія виконується кожні 3 секунди; аварійне закриття може втратити останні секунди копії. Для штатного виходу використовуйте **«Стоп»**.

### Надійність профілю та офлайн-режим

Профілі та прогрес зберігаються на пристрої. Застосунок запитує **постійне сховище**, а його фактичний статус і приблизний обсяг показує в налаштуваннях. Вибраний профіль пам’ятається між запусками. Плеєр показує **`RMS ✓ час`** після підтвердження копії базою. Дві попередні різні версії RMS доступні через **«Збереження» → «Автоматичні попередні копії»**; помилка нового запису не видаляє раніше підтверджені дані.

Для відновлення після очищення даних застосунку потрібен окремий файл: **«Налаштування» → «Експорт профілю» → зберегти ZIP у «Файлах» / на іншому носії**. Постійне сховище та локальні автокопії не захищають від видалення даних користувачем чи втрати телефона.

**Повністю автономна Java JVM ще не реалізована:** оболонка, бібліотека, імпорт/експорт і збереження доступні без мережі, а новий запуск CheerpJ потребує інтернету. Повний звіт із вимірюванням мережевих залежностей, обмеженнями iOS та варіантами автономного рушія: **[OFFLINE-AND-STORAGE.md](docs/OFFLINE-AND-STORAGE.md)**.

Профілі не синхронізуються з сервером. Перед очищенням даних браузера експортуйте архів. У налаштуваннях також можна запросити постійне сховище.

## Встановлення як PWA

- **Chrome / Edge:** натисніть **«Встановити»**, коли з’явиться пропозиція, або виберіть встановлення застосунку в меню браузера.
- **iPhone / iPad:** відкрийте HTTPS-адресу в Safari → **Поділитися → На початковий екран**.
- Довідка доступна в **Налаштування → Встановлення застосунку**. Системний діалог залежить від браузера.

Для локальної PWA після початкового налаштування зупиніть dev-сервер і запустіть production-версію:

```bash
npm run build
npm run pwa
```

Відкрийте **http://127.0.0.1:5173/** у тому самому браузері: команда зберігає порт попереднього dev-запуску, тому дані цього origin залишаються доступними.

**Офлайн працюють:** попередньо закешована оболонка та локальна бібліотека. **Новий запуск гри потребує інтернету** для CheerpJ CDN і доступу до сервера з ресурсами емулятора. Локальна PWA також потребує запущеного сервера для цих ресурсів; встановлення не створює самостійний desktop-пакет із JVM.

**Оновлення:** нова версія чекає кнопки **«Оновити»**. Активний рушій у будь-якій вкладці блокує перезапуск до зупинки гри. IndexedDB при оновленні не очищується.

Для розробки після встановлення production-PWA використовуйте `npm run dev -- --port 5174`: це окремий origin без попередньої закешованої оболонки. Деталі: **[PWA.md](docs/PWA.md)**.

## GitHub Actions → Docker → aaPanel

Кожен push у `main` запускає **[Test, build and deploy](https://github.com/valikoshka1996/Retro-Java-Emulator-PWA/actions/workflows/deploy.yml)**:

```text
Тести → production build → браузерні перевірки → Docker build
      → Docker smoke test → SSH/SCP → контейнер → healthcheck
```

Pull request проходить перевірки без SSH-деплою. Повторний запуск: **Actions → Test, build and deploy → Run workflow → main**. Образ передається на сервер безпосередньо; токени Docker Hub / GHCR не потрібні.

### 1. Secrets

У **Settings → Secrets and variables → Actions → Secrets**:

| Secret      | Значення                                                                 |
| ----------- | ------------------------------------------------------------------------ |
| `IP_SERVER` | IP / DNS сервера без протоколу та порту                                  |
| `SSH_KEY`   | Повний приватний SSH-ключ без passphrase зі справжніми переносами рядків |
| `USER`      | SSH-користувач; для поточної конфігурації — `root`                       |

Необов’язкові **Variables**: `SSH_PORT` — типово `22`, `APP_PORT` — типово `18087`. Перевірений host key можна зафіксувати додатковим secret `SSH_KNOWN_HOSTS`.

### 2. Сервер

Потрібні Docker, Compose v2 з `--wait --wait-timeout`, а також `bash`, `curl`, `ss`, `flock`, `sha256sum`. Поточний образ розрахований на **Linux amd64 / x86_64**; невідповідна архітектура відхиляється перед запуском.

Деплой використовує окремий Compose-проєкт **`retro-java-emulator-pwa`**, каталог **`/opt/retro-java-emulator-pwa`** та адресу **`127.0.0.1:18087`**. Контейнер працює без root, із read-only filesystem та обмеженнями ресурсів.

Інші контейнери й конфігурації сайтів не редагуються. Docker daemon / aaPanel не перезапускаються; глобальний prune не виконується. Конфлікт порту перериває деплой. Невдала перевірка нового релізу запускає відкат до попереднього успішного, якщо він існує.

### 3. Reverse proxy в aaPanel

Створіть **окремий** reverse proxy project:

| Поле            | Значення                              |
| --------------- | ------------------------------------- |
| Тип             | `Default project`                     |
| Show Proxy Path | Вимкнено; якщо використовується — `/` |
| Domain name     | `retrojava.pp.ua`                     |
| Target — тип    | `URL address`                         |
| Target — адреса | **`http://127.0.0.1:18087`**          |
| Send Host       | `$http_host`                          |
| URL Rewrite     | Порожньо                              |
| Remark          | `Java Retro Emulator PWA`             |

Після **Confirm** перевірте DNS A-запис домену, випустіть Let's Encrypt у **SSL** та ввімкніть **Force HTTPS**. Для цього proxy вимкніть додатковий cache і content replacement. Заголовки `Range` / `Content-Range` мають проходити без підміни.

### 4. Перевірка

На сервері:

```bash
curl -f http://127.0.0.1:18087/healthz
docker ps --filter label=com.docker.compose.project=retro-java-emulator-pwa
```

Після налаштування домену:

```bash
curl -I https://retrojava.pp.ua/sw.js
curl -sS -D - -o /dev/null -H 'Range: bytes=0-15' \
  https://retrojava.pp.ua/engine/freej2me-web.jar
```

Очікується `no-store` для worker і **HTTP 206** для часткового завантаження JAR. Якщо зовнішній proxy прибирає Range й повертає HTTP 200, Java Retro завантажує невеликі JAR рушія у файлову систему CheerpJ в пам’яті. Це дозволяє запуск без зміни глобальних налаштувань proxy. Потім відкрийте сайт і перевірте RMS Probe.

Повні команди, діагностика, логи та ручний відкат: **[DEPLOYMENT.md](docs/DEPLOYMENT.md)**.

> Перехід із localhost на production-домен — зміна origin. Перенесіть локальний профіль через ZIP: ігри та RMS не включені в Docker-образ.

## Питання та відповіді

<details>
<summary><strong>Гра не запускається або екран неправильного розміру</strong></summary>

Зупиніть гру й відкрийте **Налаштування → Advanced**. Перевірте роздільність, спробуйте інший телефон, вимкнення звуку або queued paint. Статичний аналіз не гарантує сумісності. Для завислого рушія є аварійне завершення в діагностиці; незавершені записи можуть бути втрачені.

</details>

<details>
<summary><strong>Після зміни адреси бібліотека порожня</strong></summary>

Перевірте браузер, профіль, протокол, host і порт. `http://127.0.0.1:5173`, `http://localhost:5173` і `https://retrojava.pp.ua` мають окремі сховища. Відкрийте стару адресу, експортуйте профіль та імпортуйте ZIP на новій. Інкогніто й очищення даних сайту теж впливають на зберігання.

</details>

<details>
<summary><strong>Чому встановлена PWA просить інтернет?</strong></summary>

Офлайн-кеш містить оболонку. JVM CheerpJ завантажується із зовнішнього CDN, ресурси емулятора — із сервера застосунку. Встановлення не робить runtime повністю офлайн. Уже запущена гра не завершується автоматично лише через втрату з’єднання.

</details>

<details>
<summary><strong>Оновлення не застосовується</strong></summary>

Зупиніть гру в усіх вкладках цього сайту й натисніть **«Оновити»**. Наявність нової версії можна перевірити в налаштуваннях. Не очищайте IndexedDB для оновлення: це видалить локальні дані, а не лише кеш оболонки.

</details>

<details>
<summary><strong>aaPanel показує 502 або JAR не завантажується</strong></summary>

Перевірте локальний `/healthz`, статус Actions і Target цього proxy project. JAR має повертати HTTP 206 на запит Range. Вимкніть додатковий proxy cache / content replacement і перевірте порожній URL Rewrite. Детальна діагностика та відкат — у [DEPLOYMENT.md](docs/DEPLOYMENT.md).

</details>

## Архітектура та документація

**React · TypeScript · Vite · Zustand · Dexie / IndexedDB · FreeJ2ME Web · CheerpJ · Nginx · Docker**

```text
src/                     UI, бібліотека, імпорт, сховище й EmulatorAdapter
src/pwa/                 встановлення, service worker та оновлення
build/pwa.ts             генерація versioned shell cache
engine/                  iframe shell і контрольований JS bridge
java/                    Java bridge та власний RMS Probe
scripts/                 підготовка рушія й Java build
vendor/freej2me-web/      зафіксований upstream із вихідними кодами
public/icons/            SVG, PNG, maskable та Apple іконки
public/engine/           згенерований runtime; не редагувати вручну
tests/                   unit, E2E та production PWA перевірки
deploy/                  Nginx, Compose, SSH deployment і smoke test
.github/workflows/       перевірки та деплой
docs/                    детальні технічні інструкції
```

| Документ                            | Зміст                                      |
| ----------------------------------- | ------------------------------------------ |
| [ENGINE.md](docs/ENGINE.md)         | Upstream, інтеграція, RMS і межі ізоляції  |
| [PWA.md](docs/PWA.md)               | Worker, кеш, встановлення й оновлення      |

Локальні профілі розділяють дані застосунку, але не є security boundary проти навмисно шкідливого Java-коду в одному origin. Межі браузерної ізоляції та узгодженості RMS-копій описані в дослідженні рушія.
