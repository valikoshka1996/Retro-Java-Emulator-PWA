# Java Retro Emulator

Локальний вебзастосунок українською для власних Java ME ігор. Реальний FreeJ2ME Web працює через CheerpJ у браузері; ігровий екран не імітується.

GitHub Actions і Docker-деплой на сервер з aaPanel: **[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)**. Workflow використовує secrets `IP_SERVER`, `SSH_KEY`, `USER`; типовий reverse proxy Target — `http://127.0.0.1:18087`.

## Запуск у Windows / macOS / Linux

Потрібні Node.js 22.12+ (перевірено на 24.15), npm, Java **8** для побудови невеликого bridge-модуля. JDK не потрібний: скрипт завантажує Eclipse ECJ 4.6.1 з Maven Central. Рушій та його вихідний код вже є у `vendor/`.

```sh
npm ci
npm run engine:prepare
npm run dev
```

Відкрити **http://127.0.0.1:5173/**. Зберігайте той самий host і порт: `localhost`, `127.0.0.1` та різні порти мають окремі сховища. Перший запуск CheerpJ потребує інтернету й може тривати кілька хвилин.

1. Створіть профіль.
2. Перетягніть власний `.jar` або виберіть JAR та відповідний однойменний JAD.
3. Перегляньте аналіз. Роздільність без явних метаданих — припущення, яке можна змінити в Advanced.
4. Натисніть «Грати». Стрілки — напрямки, Enter — OK, F1/F2 — soft keys; усі дії можна перепризначити.
5. Зберігайтеся всередині гри. Натисніть **«Стоп» перед закриттям**, щоб дочекатися `destroyApp(true)` та фінальної копії RMS в IndexedDB.
6. Відкрийте той самий браузер, профіль і гру — внутрішні збереження буде відновлено.

Для перевірки без сторонніх ігор натисніть **«Додати RMS Probe»**. Це власний відкритий тестовий MIDlet: Enter збільшує й записує лічильник, 1 відтворює тон, 0 завершує MIDlet.

## PWA: встановлення на пристрій

PWA вже підключено. Для встановлення використовуйте **production-збірку**:

```sh
npm run build
npm run pwa
```

Перед цим зупиніть dev-сервер на порту 5173. Відкрийте **http://127.0.0.1:5173/** у тому самому браузері: команда `pwa` зберігає origin попереднього dev-запуску, тому існуючі профілі, JAR і RMS залишаться доступними. Якщо раніше використовували `localhost`, відкривайте саме `http://localhost:5173/`.

- Chrome / Edge: натисніть **«Встановити»** у застосунку, коли браузер дозволить показати пропозицію; також доступне встановлення через меню браузера. Довідка є в **Налаштування → Встановлення застосунку**.
- iPhone / iPad: Safari → **Поділитися → На початковий екран**. На фізичному телефоні сайт має бути доступний через **HTTPS**; `127.0.0.1` комп’ютера не є адресою комп’ютера для телефона. Зовнішнє розміщення поки не налаштоване.
- Після встановлення з’являється власна іконка, застосунок відкривається у standalone-вікні. Фактичний системний діалог встановлення залежить від браузера.

Після першого успішного відкриття production-версії оболонка, іконки й інтерфейс кешуються для офлайн-запуску. **Бібліотеку та локальні дані можна відкрити без мережі; новий запуск гри потребує інтернету через CheerpJ CDN.** PWA не перетворює зовнішній JVM runtime на повністю офлайн-емулятор. JAR, RMS і профілі зберігаються в IndexedDB, а не в service worker cache.

Нова версія очікує натискання **«Оновити»**. Перед активацією перевіряється блокування рушія у всіх вкладках: під час активної гри оновлення відхиляється з поясненням. Перезапуск виконується після зупинки гри; кеші інших застосунків і IndexedDB не очищуються. `/engine/*`, запити `Range` і CheerpJ CDN service worker не перехоплює.

`npm run dev` не реєструє service worker. Якщо на origin 5173 уже встановлена production-PWA, для подальшої розробки використовуйте окремий origin: `npm run dev -- --port 5174`; інакше раніше встановлений worker продовжить віддавати production-оболонку. Очищати дані браузера для переходу між режимами не потрібно.

Перевірка: `npm run build` → `npm run test:pwa`. Додаткові деталі — [docs/PWA.md](docs/PWA.md).

## Production-збірка

```sh
npm run engine:prepare
npm run build
npm run preview
```

`dist/` можна обслуговувати статично, **з кореня домену**, через HTTPS або loopback HTTP. Сервер має підтримувати byte ranges для JAR. Vite dev/preview перевірено з цим рушієм. Порт preview — 4173: його бібліотека буде окремою від dev-порту 5173. Розгортання на зовнішній сервіс у цьому завданні не виконувалося.

## Реалізовано

- Кілька локальних профілів з аватарами, окремими бібліотеками, конфігураціями, RMS, слотами й історією сесій.
- Імпорт JAR/JAD, обмеження розміру, валідація ZIP central directory, шляхів, сумарного розпакування, коефіцієнта стиснення та CRC; SHA-256 і дедуплікація в межах профілю.
- Manifest continuation lines, MIDlet entries, версії MIDP/CLDC, PNG-іконка, статичне визначення class references API, confidence та пояснення припущень.
- Картки, пошук, сортування, обрані, подробиці гри, видалення JAR з окремим вибором щодо RMS/слотів.
- Адаптер `EmulatorAdapter`: справжні запуск, завершення, перезапуск, клавіші, screenshot, експорт та імпорт RMS, конфігурація і capabilities.
- Телефонні пресети, роздільність включно з custom, вибір MIDlet, sound on/off, integer/fit scaling, fullscreen, FPS limit і підтримані compatibility flags.
- Редактор 19 дій, перевірка конфліктів, пресети, одночасні натискання, repeat/release, Gamepad API та сенсорна клавіатура з pointer capture.
- RMS у файловій системі CheerpJ та двійкові ZIP-копії в IndexedDB; автокопія кожні 3 с, копія на штатному виході.
- До п’яти слотів RMS зі скріншотом, назвою, датою, відновленням, перейменуванням, видаленням та експортом. Відновлення й імпорт лише після зупинки гри.
- Експорт/імпорт профілю у ZIP: JAR, JAD, конфігурація, RMS, слоти, скріншоти й історія; імпорт атомарно створює нові ID.
- Оцінка використаного сховища, запит persistent storage, повідомлення quota/errors, Web Locks для одного активного рушія між вкладками.
- PWA manifest, звичайні та maskable PNG-іконки, iOS touch icon, встановлення, офлайн-оболонка і керовані оновлення без перезапуску активної гри.

## Структура

```text
src/
  types.ts             типізовані сутності
  db.ts                Dexie, schema v1 → v2, профілі, RMS, слоти, архіви
  archive.ts           перевірка ZIP до розпакування та CRC
  importer.ts          manifest/JAR та CompatibilityAnalyzer
  config.ts            параметри, дії, пресети, валідація
  emulator.ts          EmulatorAdapter / FreeJ2MEAdapter, RPC і lifecycle
  store.ts, i18n.ts    Zustand та початковий словник локалізації
  ui/App.tsx           екрани, форми, бібліотека, плеєр
  style.css            адаптивна темна тема, клавіатурний фокус
engine/                контрольований JS bridge і iframe shell
src/pwa/               service worker, реєстрація, встановлення й оновлення
build/pwa.ts           генерація versioned shell cache під час production build
java/                  RetroBridge та власний RmsProbe MIDlet
scripts/               підготовка runtime і побудова Java через ECJ
vendor/freej2me-web/    зафіксований upstream з вихідними кодами
public/engine/         згенерований runtime, не редагувати вручну
public/fixtures/       власний тестовий JAR
tests/                 модульні тести та браузерні інтеграційні перевірки
docs/                  дослідження рушія, feasibility і ручні перевірки
```

## Перевірки

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:pwa
```

Модульні тести використовують fake-indexeddb; вони не замінюють запуск JVM. Окремий Playwright-тест запускає **справжній MIDlet** у Chromium із постійним профілем браузера, перевіряє ненульовий аудіосигнал, ввід, створення RMS-слота, завершує процес браузера й перевіряє читання того самого запису після повторного запуску. Інший браузерний тест перевіряє UI, клавіатуру, пошук, профілі, архів і ширину 390 px. Для E2E потрібен доступ до CDN CheerpJ. Результати конкретного прогону — у [docs/TESTING.md](docs/TESTING.md).

## Межі підтримки

| Можливість | Стан |
| --- | --- |
| RMS | Реалізовано; запис/читання через повне закриття браузера перевірено на власному MIDlet |
| Backup Slots | Реалізовано; це копії постійних RMS, не стан виконання |
| Full State Snapshots | Недоступні, `snapshots: false`; див. [feasibility](docs/SNAPSHOTS.md) |
| M3G / JSR-184 | Є в upstream, WebGL 2; реальні 3D-ігри в цьому прогоні не тестувалися |
| Mascot Capsule | Окремий upstream API v3, WebGL 2; v1/v2 не заявляються |
| Звук | Перевірений tone/MIDI-вихід; сумісність конкретних AMR/MP3/video залежить від upstream |
| MIDP / CLDC | Аналізуються; перемикача версій JVM немає |
| Samsung | Немає окремого пресету; proprietary API потребують перевірки |
| Пауза | Надійного lifecycle API у цій інтеграції немає; UI не показує фальшиву паузу |
| Загальна гучність | Не заявляється; є sound on/off і системна гучність браузера |
| Офлайн | Бібліотека локальна, але запуск JVM залежить від зовнішнього CheerpJ CDN |

Не гарантується сумісність з усіма J2ME-іграми. Повна автоматична локалізація ще не винесена: `i18n.ts` задає початковий словник, решта українських текстів розташована у компонентах.

При раптовому закритті/падінні між автокопіями можуть втратитися останні секунди **копії** RMS: при наступному запуску джерелом є IndexedDB. Немає обіцянки атомарного експорту RMS під час багатопотокового запису гри. Штатний «Стоп» викликає `destroyApp(true)` перед фінальною копією; завислий destroy можна завершити аварійною кнопкою, без заяви про успіх збереження.

Локальні профілі — розділення даних застосунку, **не security boundary проти навмисно ворожого Java-коду**. JVM працює в браузерній пісочниці, але MIDlet теоретично може використовувати доступні Java API до спільної файлової системи/мережі CheerpJ. Не запускайте недовірені JAR на origin з цінними даними. JAR не завантажуються на сервер застосунком; браузер звертається до CDN за runtime. Див. [дослідження](docs/ENGINE.md).

Власний код — GPL-3.0-or-later. FreeJ2ME та сторонні компоненти збережені з їхніми заголовками й [LICENSE](LICENSE); CheerpJ має окремі [умови використання](https://cheerpj.com/docs/licensing.html). Наступні покращення: матриця перевірених 2D/3D-ігор, тести Firefox/Safari й фізичного gamepad, інтеграція синхронного підтвердження кожного RMS-запису, додаткові персистентні API поза RMS, аналіз у Worker із можливістю скасування, розширена локалізація, винесення UI-компонентів у окремі модулі. Повні snapshots потребують іншої VM або офіційного API CheerpJ.
