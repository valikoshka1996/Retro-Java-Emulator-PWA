# Магазин Java Retro

Магазин і локальна бібліотека працюють окремо. Адміністратор публікує ігри на сервері, гравець встановлює JAR у свій локальний профіль одним натисканням. Профіль, RMS та клавіатура на сервер не передаються. Видалення гри з магазину не зачіпає встановлених копій.

## Сервер і доступ

Docker Compose додає один контейнер `repository` у приватну мережу `internal: true`. Контейнер не публікує порт на хості й не має виходу в інтернет. З ним спілкується лише контейнер `web` через `/api/repository/`. Зовнішній порт застосунку залишається `127.0.0.1:18087`; нових правил aaPanel або портів 80/443 не потрібно.

Це ізоляція backend-контейнера. Публічні HTTP-запити каталогу й завантаження опублікованих JAR доступні через домен: браузерний PWA не може зберігати секрет, який надійно відрізнить його від іншого HTTP-клієнта. CORS не є автентифікацією. Якщо потрібен приватний каталог для конкретних користувачів, додайте окремі серверні облікові записи; локальний профіль не доводить серверну особу.

Адміністрування захищене scrypt-паролем, випадковою HttpOnly/SameSite=Strict cookie, перевіркою Origin та лімітом спроб входу. HTTPS додає Secure cookie. Сесія діє 8 годин і скидається при перезапуску backend. Пароль та SSH-ключі у frontend не вбудовуються.

## Перший вхід

Після першого успішного деплою відкрийте термінал aaPanel і виконайте:

```bash
cd /opt/retro-java-emulator-pwa
docker compose -p retro-java-emulator-pwa --env-file current/release.env -f current/compose.yaml exec -T repository cat /data/admin-credentials.txt
```

Скопіюйте випадковий пароль у менеджер паролів. Відкрийте **Магазин → Адміністрування → Вхід**. Файл доступний лише всередині серверного тому; він не виводиться в GitHub Actions. Кожен тестовий запуск використовує окремий том/каталог і тестовий пароль.

## Наповнення каталогу

1. «Додати JAR» дозволяє вибрати кілька файлів. «Імпортувати папку» обробляє JAR у підпапках послідовно з індикатором поточного файла. Виберіть створену вами локальну папку `repository`.
2. Кожен JAR перевіряється до 32 МБ; архів перевіряється на небезпечні шляхи, CRC, ліміт розпакування, існування MIDlet-класу. Java-код на сервері не запускається.
3. З manifest витягаються назва, розробник, версія, MIDP/CLDC, MIDlet-класи, PNG-іконка та відомі параметри екрана. Якщо розмір знайдено лише в імені файла, UI показує це джерело; інакше 240×320 є припущенням. Статичний аналіз API не гарантує сумісності.
4. Нові записи — чернетки. У редакторі задайте назву, довільний жанр, опис, теги, ширину/висоту, рекомендацію та увімкніть «Опублікувати». Для пакетної публікації є «Опублікувати всі чернетки». Редагується JSON-метадата, JAR зберігається незмінним за SHA-256.
5. Повторне додавання того самого JAR не дублює запис і не перезаписує ручні описи. Інша версія чи інший екран у відмінному JAR — окрема гра.
6. Видалення вимагає окремого підтвердження. Спочатку запис прибирається з каталогу, потім видаляються його JAR та іконка. Чернетки недоступні звичайним відвідувачам навіть за прямим URL.

Інсталяція перевіряє розмір та SHA-256 завантаженого JAR перед локальним імпортом. Назва й розмір екрана з каталогу стають початковими локальними параметрами; наступне редагування каталогу не переписує налаштування чи збереження вже встановленої гри.

Бінарні ігри з `repository/` не входять у Git, build-контекст Docker чи GitHub Actions. Додавайте до магазину файли, які маєте право поширювати.

## Постійні дані й резервні копії

Том `retro-java-emulator-pwa_repository-data` зберігає `catalog.json`, `jars/`, `icons/`, `auth.json` та приватний файл першого пароля. Метадані змінюються послідовно через запис тимчасового файла, fsync та atomic rename. При помилці запису поточний каталог не підміняється. Перезапуск чи звичайний реліз не видаляє том. Це один процес backend; не запускайте декілька реплік з одним каталогом.

Для узгодженої резервної копії короткочасно зупиніть лише repository, скопіюйте весь `/data` і запустіть його знову. Приклад через термінал aaPanel:

```bash
cd /opt/retro-java-emulator-pwa
docker compose -p retro-java-emulator-pwa --env-file current/release.env -f current/compose.yaml stop repository
docker compose -p retro-java-emulator-pwa --env-file current/release.env -f current/compose.yaml cp repository:/data ./repository-backup
docker compose -p retro-java-emulator-pwa --env-file current/release.env -f current/compose.yaml start repository
```

Каталог резервної копії має бути новим; збережіть його поза сервером і захистіть права доступу, бо він містить адміністративні дані. Під час копіювання магазин недоступний, локальні бібліотеки працюють. Не використовуйте `docker compose down -v` чи глобальний Docker prune.

## Локальна розробка

```bash
npm run repository:build
npm run repository:start
# у другому терміналі
npm run dev
```

Backend слухає 8081, Vite проксіює `/api/repository`. Локальний каталог `repository-data` ігнорується Git; пароль першого входу міститься в ньому. Автотести API: `npm test`. Повний браузерний сценарій: `npm run build && npm run repository:build && npm run test:repository`.
