# Перевірки

## Поточні перевірки захисту даних

Набір містить **25 unit**, **5 E2E** і **7 production PWA** сценаріїв. Додано міграцію реальної бази v2 → v3 із профілем/JAR/RMS, `strict` durability, ротацію й дедуплікацію двох автокопій, перевірку чужого профілю, відкат усієї транзакції при `QuotaExceededError`, некоректне RMS, відмову/відсутність Storage API. Офлайн-сценарій повністю закриває процес браузера, повторно відкриває його без мережі, перевіряє вибраний профіль, відновлює попереднє RMS, завантажує ZIP і перевіряє його вміст, потім імпортує профіль без мережі. Поточні офлайн-межі й критерії фізичного iPhone описані в [OFFLINE-AND-STORAGE.md](OFFLINE-AND-STORAGE.md).

Справжній MIDlet додатково проходить `PROBE_SAVED:2 → підтвердження RMS у плеєрі → закриття браузера без «Стоп» → PROBE_READ:2`. Це перевірка вже підтвердженої автокопії, а не обіцянка збереження останнього непідтвердженого запису при раптовому завершенні ОС.

Результати попередніх етапів нижче збережені як історія перевірок.

## Поточний прогін після змін мобільного плеєра

**20/20 unit**, **5/5 E2E**, TypeScript/Vite build пройдено. Нові перевірки: Fullscreen API відсутній, запит відхилено, справжній native fullscreen включає клавіатуру, вихід відновлює інтерфейс, діалог налаштувань доступний у fullscreen. Перевірено viewport 390×844, 375×667, 844×390, 667×375, максимальні розміри клавіш, теми та збереження після reload без перезапуску поточної гри. CDP надсилає одночасні дотики «↑ + OK»; перевіряються натискання й відпускання обох клавіш через bridge.

Мобільні layout-тести використовують контрольований bridge без JVM. Окремий тест зі справжнім CheerpJ натискає екранний OK у повноекранному мобільному плеєрі: `PROBE_SAVED:1`, потім повністю закриває браузер і перевіряє `PROBE_READ:1`. Unit-тести перевіряють старі конфігурації без `touchControls`, валідацію меж і перенесення вигляду через архів без втрати інших параметрів гри. Фізичний iPhone та встановлена на ньому PWA потребують ручної перевірки.

Production PWA: **6/6 пройдено**, включно з реальним MIDlet та збереженнями під service worker. Додатковий прогін WebKit 27.2 на Windows зупинився на імпорті JAR через `UnknownError: Error preparing Blob/File data to be stored in object store` ще до відкриття плеєра; він не підтверджує поведінку iOS. Фізичний iPhone залишається ручною перевіркою.

Нижче — результати попередніх етапів і ручні сценарії.

Середовище: Windows, Node 24.15, Java 8.0.482, Chromium 156 через Playwright. Дата: 23 жовтня 2026.

## Автоматизовані

- `npm test`: **18/18 пройдено** — manifest/JAD, API analysis, SHA/dedup, zip bomb, traversal, CRC, некоректні файли, profiles, повторне відкриття IndexedDB, слоти та їх ліміт, restore, архіви включно із залишеними RMS видалених ігор, атомарність некоректного import, ізоляція і видалення з/без RMS.
- `npm run build`: **пройдено**, TypeScript + production Vite build.
- `npm run test:e2e`: справжній CheerpJ/FreeJ2ME, без mock JVM. Перевіряє `PROBE_READ:0 → PROBE_SAVED:1 → повне закриття процесу → PROBE_READ:1`. Тон перевіряється ненульовими семплами WebAudio analyser, а не припущенням про натискання кнопки. Створюється RMS backup slot із screenshot.
- UI-перевірки: створення профілю, бібліотека, редактор клавіш, пошук, обране, експорт/імпорт нового профілю, ізоляція другого профілю, повторне завантаження й viewport 390 × 844 без горизонтального переповнення.

Скріншоти та браузерний профіль E2E знаходяться в `test-results/` і не входять до source control. Тести потребують доступу до CheerpJ CDN; збій CDN не слід видавати за успішний запуск JVM.

Фінальний браузерний прогін: **2/2 пройдено**, 21 с. `npm audit --omit=dev`: 0 відомих вразливостей. Це не перевірка сумісності всіх ігор і не аудит безпеки JVM.

## Додано під час переходу на PWA

Повторний прогін після змін: **18/18 unit**, **2/2 базових E2E**, **4/4 production PWA**; TypeScript/Vite build пройдено. PWA-тести перевіряють відсутність installability errors у Chromium DevTools Protocol, manifest і PNG-іконки, офлайн-перезавантаження бібліотеки, зрозумілу відмову нового запуску JVM без мережі, незмінність byte ranges, реальний MIDlet/RMS під worker та очікування оновлення під час engine lock. Окремо перевіряється відмова install prompt; цей сценарій використовує контрольовану подію, а не системний інсталяційний діалог. Деталі — [PWA.md](PWA.md).

## Ручна перевірка

Після виправлення reverse proxy додано регресійний запуск справжнього MIDlet при HTTP 200 замість Range/206 та окремі сценарії HTTP 502 і відсутнього JS-модуля. Production PWA набір: **6/6 пройдено**. Опис завантаження `/str/` — у [ENGINE.md](ENGINE.md).

1. Створіть два профілі; додайте RMS Probe у перший, у другому бібліотека порожня.
2. Запустіть Probe у першому. На екрані `RMS READ: 0`; Enter → `RMS SAVED: 1`; 1 → чутний тон.
3. Відкрийте «Збереження», створіть слот A. Ще раз Enter → 2. Натисніть «Стоп», дочекайтеся «Гру зупинено».
4. Відновіть слот A після зупинки. Новий запуск має читати 1. Перейменуйте/експортуйте слот, перевірте максимум 5 слотів. Імпортуйте експортований RMS через «Імпорт RMS» тільки після зупинки.
5. Закрийте всі вікна браузера. Повторно відкрийте той самий origin і профіль. Переконайтеся, що Probe читає те саме значення.
6. Додайте той самий JAR у другий профіль. Початкове значення має бути 0. Перевірте незалежне збереження.
7. Експортуйте перший профіль, імпортуйте архів; створиться новий профіль із грою, параметрами, RMS та слотами. Перевірте запуск і зміну копії незалежно від оригіналу.
8. Змініть клавіші, навмисно створіть конфлікт — збереження має бути заблоковано. Перевірте одночасний напрямок + fire, release при blur, фізичний gamepad і сенсорні кнопки.
9. На мобільному перевірте portrait/landscape, повноекранний режим, cancel дотику та довге утримання. На десктопі перевірте фокус форм/діалогів і Tab/Escape.
10. Перевірте сумісні ліцензійно дозволені 2D, M3G і Mascot v3 ігри. Ці сторонні ігри не додані до репозиторію. Реальні 3D-ігри, Safari/Firefox і фізичні контролери в поточному автоматизованому прогоні не перевірені.

Падіння/kill браузера без «Стоп» — окремий негативний сценарій: останні секунди можуть не бути в IndexedDB mirror. Жодної гарантії full snapshot немає.
