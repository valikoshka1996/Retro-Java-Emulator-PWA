# PWA Java Retro

## Поведінка

`public/manifest.webmanifest`: стабільний `id: /`, start URL і scope `/`, standalone, українська мова, темна тема, PNG 192/512, окрема maskable 512. `index.html` підключає manifest, SVG favicon і Apple touch icon 180. Іконки відтворюють наявний знак геймпада; вихідний SVG збережено. За потреби відновлення PNG: `node scripts/generate-icons.mjs` (потребує Playwright Chromium; готові іконки вже є в `public/icons/`).

`build/pwa.ts` генерує `dist/sw.js` після Vite build. Версія кешу обчислюється SHA-256 з worker-коду, HTML, JS/CSS та іконок. Той самий build дає ту саму версію. Precache обмежений явним переліком shell assets; JAR/WASM/media з `public/engine` до нього не потрапляють.

Worker використовує cache-first для оболонки `/`, `/index.html` і build assets. Навігація до `/engine/player.html` ніколи не отримує React HTML fallback. Cross-origin, не-GET, Range, engine, fixtures та будь-які URL поза allowlist проходять у браузерну мережу без `respondWith`. Це зберігає потрібну CheerpJ семантику byte ranges і не створює великий runtime cache.

Установлення worker завершується лише після успішного `cache.addAll`. Нова версія не викликає `skipWaiting` автоматично. Кнопка «Оновити» перевіряє той самий origin-wide Web Lock, що й JVM. Якщо рушій активний у будь-якій вкладці, UI показує пояснення й не надсилає команду активації. За відсутності lock-конфлікту worker активується і поточне вікно перезавантажується. Під час активації очищуються лише застарілі кеші префікса `java-retro-shell-`; IndexedDB не змінюється.

`src/pwa/client.ts` реєструє worker тільки у production та secure context. `beforeinstallprompt` використовується лише після отримання реальної події від браузера; відмова не видається за встановлення. У браузерах без цієї події доступна інструкція через налаштування. Немає обіцянки, що кнопка системного встановлення з’явиться в усіх браузерах. Для iOS наведено шлях через Safari Share menu.

## Дані й офлайн

PWA і звичайна вкладка використовують IndexedDB свого origin. Немає міграції чи перейменування бази. Для збереження наявної локальної бібліотеки `npm run pwa` обслуговує production build на попередньому порту **5173**; `preview` / PWA tests використовують **4173** і мають окрему базу. Якщо origin змінюється, перенесіть профіль через ZIP.

Офлайн можна відкрити попередньо закешований інтерфейс і працювати з локальною бібліотекою. Для нового запуску JVM потрібен інтернет. Кнопка запуску офлайн повертає зрозуміле повідомлення одразу. Втрата мережі не завершує вже запущену JVM автоматично. Повна офлайн-робота CheerpJ не реалізована і не заявляється.

Встановлення на фізичний телефон потребує доступного телефону HTTPS-origin. Локальне встановлення на комп’ютері можна перевірити через loopback. Встановлена локальна PWA не замінює сервер назавжди: офлайн-оболонка відкриється без нього, але ресурси рушія з `/engine/*` потребують доступного сервера. Для постійного використання потрібне розміщення або запущений локальний сервер.

## Ігровий режим на телефоні

Повний екран включає гру та сенсорну клавіатуру. Виклик стандартного або WebKit Fullscreen API перевіряється перед використанням. За відсутності API чи відмови браузера відкривається режим на всю доступну область вікна (`100dvh`) з урахуванням safe-area; системні панелі iOS не приховуються примусово. Вихід повертає прокручування та панелі застосунку. Налаштування клавіатури й RMS доступні всередині цього режиму.

Розмір і колір клавіатури зберігаються в конфігурації гри. Старі бібліотеки та архіви без поля `touchControls` використовують стандартний вигляд без міграції даних.

Поведінка браузерних API: [MDN Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API), [динамічні одиниці viewport](https://developer.mozilla.org/en-US/docs/Web/CSS/length).

## Автоматизовані перевірки

`npm run build` → `npm run test:pwa` запускає окремий production preview. Сценарії:

1. Manifest і розміри PNG; активація worker; створення профілю й імпорт власного MIDlet; відключення мережі та перезавантаження; бібліотека зберігається; новий запуск гри офлайн пояснює обмеження; кеш не містить engine/fixtures.
2. Справжній запит `Range: bytes=0-15` повертає HTTP 206 і 16 байтів під керуванням worker. Справжній FreeJ2ME запускає RMS Probe, обробляє Enter і записує RMS.
3. Подія install prompt з контрольованою відмовою перевіряє UI-обробник. Це тест логіки UI, **не** автоматизація системного встановлення.
4. Сервер отримує нову версію того самого worker; вона чекає. Утримання engine lock блокує оновлення. Після його звільнення оновлення активується, сторінка перезавантажується, бібліотека лишається; сторонній cache зберігається. Тимчасова зміна `dist/sw.js` повертається в `finally`.

Фактичний інсталяційний діалог Chrome/Edge, запуск зі значка Windows/Android/iOS та фізичний iPhone перевіряються вручну. Після `npm run pwa` встановіть через меню браузера, закрийте вкладку, відкрийте зі значка й перевірте профіль, гру та RMS. Потім вимкніть мережу й перевірте доступність бібліотеки. Під час переходу на новий production build перевірте «Оновити» після «Стоп».

Після виправлення запуску за reverse proxy набір містить **6 сценаріїв**: додано HTTP 502 та помилку завантаження модуля, а справжній MIDlet також перевіряється з відповідями HTTP 200 на всі JAR-запити, як при видаленні Range зовнішнім proxy. Результат: **6/6 пройдено**; `Page.getInstallabilityErrors` у Chromium повернув порожній список.

Джерела для браузерних вимог: [MDN: installable PWAs](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable), [Service workers](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers), [beforeinstallprompt](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event).
